# Scenes integration

Cached panorama playback, scene/location settings and Debug Mode controls are implemented. New scene generation is excluded from this merge; retained candidate/preparation boundaries use controlled adapters. Automated and real-app coverage is described under [Verification](#verification). ## Storage and settings

`scene_bundles` owns immutable manifest/hash/size records; a database trigger rejects updates. Canonical manifest text preserves hash-exact numeric provenance across JSON transport; JSONB is a query projection. `scene_state` owns active/previous pointers, location and a compare-and-swap revision. Neither table refers to a Thread. Files live under the instance's `files/scenes`; all asset routes inherit the existing authenticated API boundary.

Current limits are 128 MiB per bundle and 512 MiB total. Retain shipped fixtures and current/previous approved bundles; remove other approved bundles after a 24-hour publication grace period and abandoned staging after one hour. Candidate retention is separate; see [routed candidate workflow](#routed-candidate-workflow). Backups must include both scene metadata and referenced immutable files; database recovery cannot reconstruct pixels. Operational follow-up is recorded in [deferred work](../../specs/features/scenes.md#deferred-work).

The browser checks sizes, PNG headers and SHA-256 before decoding and staging a replacement. CacheStorage retains approved current/previous asset bytes; host manifest cache and phase preference remain separate. Load the cached scene before checking for updates; retain the last actually displayed scene if the client missed intermediate server activations. API/asset/decode failures preserve the last complete scene and retry at the next 30-second state check; startup falls back through saved previous and shipped Meadow panorama. `DEFAULT_SCENE_ID`, `SCENE_REPLACEMENTS` and `RETIRED_SCENE_IDS` govern selection and fallback. Startup migrates each retired selection to its matching panorama; reference assets remain readable for generation provenance.

Location is an offline searchable list of major cities with a San Francisco default. `LocationSettings` debounces input by 220 ms, aborts superseded requests and disables stale results. The injected shared Search/Popover/replacement capabilities keep input focus and popup glass stationary while result rows crossfade and resize. The selected city/coordinates/timezone persist in instance metadata. Phase selection and its astronomical anchor persist on the desktop, holding the sky across midnight and restart. External geocoding was not authorized; no search text is sent to a location service.

Settings → Appearance has one Scene dropdown. `GET /api/scenes` lists compatible saved bundles; `POST /api/scenes/select` checks the selected bundle and expected state revision before activation. Successful selection notifies workspace playback immediately; decoding still completes before replacement. New Scene is present but reports that generation is not connected yet. Settings → General owns Location. The app has no candidate review/import/preview/approval/restore flow; those UI and server endpoints were removed at the user's direction.

Settings → General owns the device-local Debug Mode preference in client `app/preferences.ts`, off by default. `Chat` mounts `SceneControls` only while enabled; its landscape icon opens the shared popup with `ScenePicker` first. `scene-tuning.ts` keeps validated local per-scene/per-cloud-type drafts outside immutable bundles. Reset restores the baseline; unmount restores normal playback. Manual time uses the selected city's date and shared astronomical clock; cloud animation pauses independently of water. Selecting a lighting phase releases manual time. The popup uses injected shared glass, select, range and status capabilities with native switches.

`profile-defaults.ts` owns the [accepted starting values](../../specs/features/scenes.md#profile-defaults). Automatic profile proposals use geometry-dependent availability, a source-derived arrangement seed and the selected style's baseline. Shipped panoramas materialize their reviewed values in immutable `-v3` manifests and reuse the original asset bytes; `-v1`/`-v2` selections migrate without mutating saved manifests. Debug cloud-style changes use that style's starting values, then retain independent local coverage, drift, shadow strength and softness adjustments. `tuningPercent`/`tuningValue` normalize panel ranges without changing renderer units; shadow strength is actual 0–100% opacity.

## Artwork and framing

Production playback uses an aspect-preserving cover crop. All image, map, cloud, shadow, star and water coordinates share that crop. Backing pixels are capped at 8,294,400 and 4096 per edge, independently of CSS coverage. The approved panoramas preserve more composition in wide windows than the former square fixtures.

Selectable Lakeside and Wooded Valley use `lake-panorama-v3` and `valley-panorama-v3`, each 3966×1586 like Meadow. Their accepted gallery inputs (`lake-02` and `valley-02`, 1983×793) used original Meadow alone as the style reference. Both received the established balanced 2× recipe and separate pinned-model preparation; sky/depth are resampled linearly, surfaces with nearest-neighbor, and tone lifting is reapplied at output size. Lakeside's classified water covers 19.51% of the source and excludes foreground foliage/banks; Valley has none. Provenance and reproduction files live in the experiment's `upscale/landscape-panoramas-2026-10-23`. Retired square Lakeside/Valley and Meadow 2× trials remain in the independent experiment, outside shipped fixtures; original Meadow stays hidden for style-reference provenance.

Artwork and lifted artwork retain their native dimensions; procedural maps/effects remain bounded to a 1600-pixel edge. Grading retains two adjacent native frames when settled. Water samples a normalized crop across the independently sized artwork and effect buffers.

`SceneHost` passively observes pointer movement over exposed sky; the canvas remains hidden from accessibility, unfocusable and transparent to pointer events. Constellation detection matches the experiment's convex hull, with a 60 CSS-pixel proximity margin, enclosing-polygon preference and overlap/exit hysteresis. Lines appear after a 180 ms dwell with a 350 ms fade; reduced motion resolves them immediately. Visibility uses the shared cover crop and cloud/terrain masks; final compositing applies the same masks as stars. Foreground controls/surfaces, touch, scroll, window exit, hidden/paused playback and scene replacement clear hover. No picker, click/touch selection, keyboard cycling or constellation announcements are installed.

Explicit lighting changes fast-forward solar lighting and catalog rotation over 1600 ms. `grading.js` shares the native-pixel recipe between still playback and `lighting-worker.js`. The worker prepares a complete 1280-pixel-wide reference day (about 25 MiB) for immediate input; settling requests only the current two native frames after 100 ms of quiet. Native frames replace the interactive cache once ready. Rapid input cancels superseded native work and continues from the current solar state; animation never generates missing native frames on the UI thread. Reduced motion and hidden/paused playback resolve to the target. Scene replacement/lift changes terminate the old worker; disposal closes both caches and releases buffers. Unsupported workers use the original CPU fallback. Artwork swaps stage completely and replace directly; no scene dissolve remains.

Cumulus coverage scales the cloud body and its shared shadow footprint instead of reducing its opacity. Overcast coverage varies a full sky sheet's optical thickness and tone. Canvas patterns sample continuously across horizontal field wraps, avoiding the transparent seams between separately drawn fractional tiles. The depth-shadow field repeats the same seeded volume footprints across and ahead/overhead of the camera; restricting it to the visible distant cloud band left foreground receivers unlit. `data-shadow-coverage` reports the proportion of near/far receivers with measurable shade for visual diagnostics, not calibrated physical coverage.

The balanced 2× recipe uses RealESRGAN_x2plus for 50% of its high-frequency difference from a Lanczos baseline; subtracting an 8-output-pixel Gaussian low-frequency difference retains the broad palette. The model/recipe hashes, licenses, raw neural alternative and matched native detail crops live in `ash_experiments/scenes/comparison-2026-10-22/upscale`. It sharpens edges while partly smoothing matte grain; it cannot recover missing source detail.

Default `meadow-panorama-v3` uses the gallery’s selected Meadow-only panorama (`meadow-03`, 1983×793) and its balanced 2× derivative (3966×1586). It has its own sky, relative-depth and surface maps from the pinned local preparation models, rather than reusing square Meadow’s geometry. The 47.26% sky mask follows the new skyline; no water was detected. Sky/depth maps use linear 2× resampling, surface classes use nearest-neighbor, and tone lifting is reapplied at artwork resolution. The experiment’s `upscale/panorama-preparation` records source-resolution outputs and model pins; the bundle records final hashes.

`meadow-only-panorama-v3` requests 3840×1536 artwork using original Midjourney Meadow as the sole style reference. `SCENE_ARTWORK_LIMITS` / `validSceneArtworkSize` enforce [SCN-04](../../specs/features/scenes.md) before preparation; rejected output retains its captured original/hash and never replaces the active scene. Landscape/vegetation/landmark/cloud choices are bounded inputs; palette, detail and framing rules stay fixed. Generation captures the exact prompt, configuration, source/reference hashes, actual output dimensions and available usage. Compare against current/previous scenes; near-duplicate appearance still requires visual review.

The experimental gallery contains actual 1983×793 panoramas. A native 3840×1536 request returned the same dimensions, so those authored images require the recorded 2× recipe. These results establish framing/style evidence, not reliable native high-resolution delivery or an API-model limit. Production generation must satisfy the decoded artwork-size contract.

## Preparation contract

The extracted worker carries forward `sky-horizon-v2+tone-lift-v1+surface-v3+depth-v1+shoreline-v1`: SegFormer B0 sky/horizon refinement, SegFormer B2 surfaces, Depth Anything V2 Small depth and conservative shoreline refinement. It uses the snapshot algorithms without fixture probes. Transformers.js 4.3.1 runs FP32 on CPU; cancellation terminates the dedicated worker. Models require explicit installation with exact commit revisions and per-file SHA-256/size locks. Playback never installs or loads them; the worker disables remote models and network fetch. The panorama authoring pass installed/hash-pinned these models in the experiment cache and ran actual offline inference in 15.2 seconds. That establishes one prepared panorama, not general model accuracy. The production host still needs an explicitly configured installation; missing models fail availability before generation.

## Routed candidate workflow

Authenticated `POST /api/scenes/events` accepts `{id, source:{name,eventId,label,url?}, occurredAt?, targetThreadId?, intent:{landscape,vegetation?,landmark?,cloudStyle?}}`. Preserve the actual source and stable event identity. The feature produces a bounded structured event for ordinary intake, deduplication, Filter/Route/assessment and the existing Run/tool executor. No dedicated Thread or new worker scheduler is created.

`scene.generate` uses existing Permissions/Decisions and cancellation. Its instance-owned event ledger admits one generation attempt per input; a repeated tool call reuses completed evidence, while interrupted/unknown outcomes require reconciliation. Preflight checks generator and model availability before dispatch. Request → generation result → preparation → profile proposal → review-required records each have one immediate Artifact source. Large PNGs and hash-checked candidate exports live under `files/scene-candidates`, separate from chat-upload expiry. Candidate storage has a 512 MiB cap, reserves 128 MiB per admitted attempt and limits history to 512 records including failed attempts; retained evidence is not automatically pruned in this slice. Full storage blocks new work without removing the approved scene.

`GET /api/scenes/candidates/:id` exports a completed candidate; `/assets/:hash` serves only its checked assets. Both use the host's authenticated boundary. Candidate manifests omit a verification record, so approved-scene publication rejects them. All four internal quality gates remain review-required, and the tool reports that the approved scene stays active. Ordered render/motion evidence and internal verification/promotion remain pending.

The production host currently configures neither a backend generator nor installed models. It reports those limitations for a routed scene request and makes no image-generation calls. The built-in Codex image tool remains an experimental authoring path, not an Ash server capability.

## Verification

Feature checks live in `packages/scenes/tests/` and `src/server/storage.test.ts`. `scene-persistence` uses real PostgreSQL and backend restarts. Electron `scene-desktop` exercises cached playback, overrides, saved city, unfocusable decorative sky, replacement retries and streaming chat; `scene-replacement` exercises complete swaps, invalid asset rejection, offline cache and unavailable WebGL. Existing layout snapshots use a fixed date/phase and reduced motion. Diagnostic attributes expose scene load latency, native/effect dimensions, grading-cache count, current hovered constellation and rolling paint mean/P95 independently of the opt-in Debug Mode controls. `scene-resolution` checks native 2048² and 3966×1586 artwork, retained fine detail, bounded effects and two adjacent grading frames. A focused reduced-motion measurement at 3840×2160 backing showed median 14–15 ms paint and 0.65–1.18 s loading; this isolates artwork/output cost with clouds/stars disabled and does not establish animated full-scene performance.

Scene pixels stay outside UI materials; scene controls receive shared select/search/status capabilities. Normal UI materials apply at every lighting phase, with no scene readability wash or backing override. Run full automated verification on the final rebased revision before integration; retained reports identify its exact source. The final focused Electron pass covered the nested Debug Mode scene picker, Escape/focus return, astronomical transitions, cache/failure retention, native water texture upgrades and minimum-width model-routing controls.

Earlier real-app review covered stacked Settings/select glass, focus return, nested scrolling, 125% zoom, forced colors and reduced motion. The Latest messages action uses the existing dense surface so transcript text cannot compete through its backing.

`scene-event-workflow`, `scene-event-interruption` and `scene-unavailable` exercise real intake, routing, Run execution, immutable Artifacts and files with a controlled generator and actual CPU worker using injected semantic outputs. They cover one provider dispatch per event, reuse after provider unavailability, source capture, authorized assets, proposed profiles, cancellation/reconciliation and missing-dependency preflight. Preparation boundary checks cover pinned-file validation, worker cancellation, aligned maps and conservative shorelines; these do not validate model accuracy.

These checks do not establish generated-scene quality, motion gate calibration, release performance targets, native macOS occlusion fidelity or coordinated disaster recovery. Inspect actual minimum/fullscreen/expanded-panel views and phase transitions before release; retain measurements with verification evidence.
